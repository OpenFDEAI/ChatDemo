# 开源优先阶梯（Reuse > Assemble > Generate）

出 Demo 的每个需求都按阶梯自上而下判断，**从零写代码是最后手段**：

1. **复用**：`gallery/` 里有预验证项目 → 直接改（换 theme.json、换术语、
   接 mock 数据）；
2. **组装**：无现成项目 → 用 `templates/base` 预制模块拼（见 demo-kit.md）；
3. **生成**：前两级覆盖不了的，才从零写，并考虑会后回填画廊。

## 双时机

- **会前侦察**（重活在这里干）：主题已知 → 深搜 GitHub 与参考产品，clone
  候选、**跑通**、做最小品牌化改造，纳入画廊。会前 10 分钟的底座优先从
  画廊出；
- **会中速搜**：聊出新需求 → 后台 subagent 搜 GitHub/Web，结果进
  `CANDIDATES.md` 短名单。**铁律：现场不 clone 陌生项目**——build 翻车
  烧掉整个回合预算；除非该项目已在画廊预验证。

## GitHub 搜索配方（速搜 subagent 用）

- 查询模式：`<领域词> <形态词>`，形态词轮换：dashboard / admin / boilerplate /
  starter / clone / open source alternative to <参考产品>；
- 中文领域补一轮英文同义词（工单→ticketing/helpdesk，进销存→inventory/ERP）；
- 每条候选记录：`repo | ★ | license | 最近提交 | 跑通成本(低/中/高) | 匹配度一句话`；
- 排序权重：license 干净 > 跑通成本低 > 匹配度 > ★ 数。★ 高但三年没提交的降权。

## 参考成熟产品（含闭源）

「做图片设计参考稿定设计、做 BI 参考帆软」：读参考产品的**公开**页面与
截图，提取信息架构、页面结构、领域术语；open-lovable 类工具可把参考网站
转成可编辑 React 骨架。**规则：只借结构与交互，不抄视觉资产**（logo、
插画、图标集、营销文案一概不碰）。

## License 规则（CANDIDATES.md 必填字段）

| License | 现场演示 | 进产品 |
|---------|----------|--------|
| MIT / Apache-2.0 / BSD | ✓ 直接改 | ✓ |
| AGPL / GPL | ✓ 可演示 | ⚠ 必须隔离，短名单标红 |
| 无 license / 未标注 | ✗ 不碰 | ✗ |

## CANDIDATES.md 格式

```markdown
# 开源候选短名单
| 时间 | 需求 | repo | ★ | license | 最近提交 | 跑通成本 | 匹配度 | 判定 |
|------|------|------|---|---------|----------|----------|--------|------|
```

判定 ∈ {现场用(画廊已验证) / 会后验证 / 弃(理由)}。

## 画廊回填（每次拜访的义务）

用过的底座、验证过的候选，收尾时按 `gallery/README.md` 的条目格式回填：
仓库、license、**实测跑通的启动命令**、品牌化适配点（theme 挂哪、术语改哪）、
适配过的客户场景。个人手艺 → 组织资产。
